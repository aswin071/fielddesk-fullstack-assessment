# Database Model

## Shared abstract models

`TimeStampedModel` provides `created_at` and `updated_at`.

`UUIDModel` provides a UUID primary key generated by the server.

`SoftDeleteModel` adds `deleted_at`, an active manager and explicit restore/hard-delete administration. QuerySet deletion performs soft deletion consistently.

`OrganisationOwnedModel` adds a required indexed organisation foreign key. It is abstract and inherited by all tenant data.

`ImmutableModel` rejects ordinary update/delete operations after creation and is used for accepted progress events and audit entries.

## Principal entities

```text
Organisation
  |-- OrganisationUser -- User
  |-- WorkOrder -- assigned_technician -> OrganisationUser
  |    |-- Attachment
  |    |-- ProgressEvent
  |    `-- AuditEntry (polymorphic target metadata)
  |-- NotificationDelivery -- NotificationAttempt
  `-- AuditEntry
```

## Organisation

- `id`, `name`, `slug`
- `storage_limit_bytes`, `storage_used_bytes`
- timestamps and active state
- unique slug

## User and OrganisationUser

The Django custom User uses email as login identity. `OrganisationUser` contains `organisation`, `user`, `role`, `is_active` and timestamps.

Constraints:

- unique `(organisation, user)`
- active role is one of Owner, Dispatcher or Technician
- indexes on `(organisation, role, is_active)`

## WorkOrder

- organisation and creator
- unique organisation-scoped reference number
- title, description, site name
- priority and status
- optional assigned technician
- optional scheduled start/end
- server-owned assignment revision used for notification deduplication
- timestamps and soft deletion

Constraints include valid paired scheduling timestamps, end after start, and technician role validation in the service. PostgreSQL overlap prevention is specified by the scheduling module.

## ProgressEvent

- organisation, work order and authenticated actor
- client `event_id`
- type, occurred time and immutable original payload JSON
- processing result metadata and accepted timestamp

Unique `(organisation, event_id)` provides idempotency. Work order, actor and organisation consistency is enforced by the service and tested.

## Attachment

- organisation, work order and uploader
- generated storage key
- sanitized display name, detected content type and byte size
- checksum and timestamps

Quota accounting locks the Organisation row during upload metadata creation/removal.

## AuditEntry

- organisation, actor (nullable for system), action
- target type and target UUID
- timestamp, correlation ID
- before and after JSON snapshots plus metadata

No normal update/delete API exists. Database privileges should be tightened further in production.

## NotificationDelivery and NotificationAttempt

Delivery has a unique deduplication key, work order, technician, status and final outcome. Each attempt records number, provider result, classification, timestamp and diagnostic message.

The unique `(work_order, assignment_revision)` boundary allows only one notification delivery for each committed assignment operation. Attempts are immutable and uniquely numbered per delivery.
