# Evaluation criteria

Gatlier will review the submission across the following areas:

| Area | Weight |
| --- | ---: |
| Security, organisation isolation and role enforcement | 20% |
| PostgreSQL design, transactions and concurrency | 18% |
| Backend and API architecture | 14% |
| Automated testing | 14% |
| Background processing and failure handling | 8% |
| Attachments, quotas and secure storage | 7% |
| Real-time communication | 6% |
| Frontend correctness and usability | 6% |
| Operations, logging and deployment awareness | 5% |
| Git history and documentation | 2% |

Reviewers will consider correctness, clarity, security, maintainability and the candidate's ability to explain technical decisions.

Particular attention will be given to:

- Enforcement of organisation isolation in the backend
- Behaviour under simultaneous or repeated requests
- Database constraints and transaction boundaries
- Meaningful failure handling and recovery
- Test quality and relevance
- Secure handling of authentication, files and secrets
- Whether the documented setup works as written
- Whether the candidate understands and can modify the submitted implementation

A polished interface does not compensate for serious security or data-integrity problems.

Following the review, Gatlier may invite the candidate to a technical discussion and a short live modification of the submitted application.
